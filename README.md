# EareSoft Store

متجر ملابس إلكتروني بواجهة React وVite وخادم Express وMongoDB.

## المتطلبات

- Node.js 22.12 أو أحدث.
- MongoDB محلي أو قاعدة MongoDB يمكن الوصول إليها من الخادم.
- npm.

## إعداد الخادم

من مجلد المشروع:

```powershell
cd back
npm ci
Copy-Item .env.example .env
```

عدّل `back/.env` وضع عنوان قاعدة البيانات في `MONGO_URI`، وقيمة سرية طويلة وفريدة في `JWT_SECRET`. غيّر `ADMIN_EMAIL` و`ADMIN_PASSWORD` قبل إنشاء حساب المدير. لا تشارك ملف `.env` أو تضع أسراره في Git.

شغّل الخادم في نافذة طرفية:

```powershell
npm run dev
```

إذا كانت قاعدة البيانات تحتوي على فهارس التقييمات القديمة، شغّل `npm run migrate:reviews` مرة واحدة من مجلد `back` قبل تشغيل الخادم. يحذف الأمر الفهرس القديم الذي كان يمنع المستخدم من تقييم أكثر من منتج، وينشئ فهارس التقييمات المرتبطة بالمنتجات.

لإنشاء حساب المدير من القيم الموجودة في `.env`، شغّل مرة واحدة:

```powershell
npm run seed:admin
```

عند بدء التشغيل، يتصل الخادم بقاعدة البيانات أولًا ثم يستمع على المنفذ المحدد في `PORT`. رابط فحص الصحة الافتراضي:

```text
http://localhost:7000/api/health
```

## إعداد الواجهة

افتح نافذة طرفية ثانية:

```powershell
cd front
npm ci
Copy-Item .env.example .env
npm run dev
```

إذا كان ملف `.env` موجودًا بالفعل، احتفظ به وتأكد أن `VITE_API_URL` يشير إلى عنوان الخادم، مثل `http://localhost:7000/api`. افتح عنوان Vite الذي يظهر في الطرفية.

## الأوامر المتاحة

| المجلد | الأمر | الغرض |
|---|---|---|
| `back` | `npm run dev` | تشغيل الخادم مع إعادة التشغيل عند تعديل الملفات |
| `back` | `npm start` | تشغيل الخادم |
| `back` | `npm run seed:admin` | إنشاء حساب المدير أو تأكيد صلاحية حسابه |
| `back` | `npm run migrate:reviews` | تحديث فهارس تقييمات المنتجات عند الترقية من النسخة القديمة |
| `back` | `npm run seed:demo -- --reset` | إعادة تهيئة قاعدة البيانات وإدخال بيانات تجريبية **(يحذف البيانات الموجودة)** |
| `front` | `npm run dev` | تشغيل خادم التطوير للواجهة |
| `front` | `npm run build` | بناء ملفات الواجهة للإنتاج |
| `front` | `npm run lint` | فحص قواعد ESLint |

## بنية المشروع

```text
back/
  src/
    config/       إعداد البيئة والاتصال
    middleware/   المصادقة والصلاحيات
    models/       مخططات MongoDB
    routes/       واجهات API حسب المجال
    scripts/      مهام تهيئة قاعدة البيانات
    index.js      تركيب التطبيق وتشغيل الخادم
  uploads/        صور المنتجات المرفوعة
front/
  src/
    components/   مكونات الواجهة المشتركة
    context/      حالة المستخدم والسلة والمفضلة
    pages/        صفحات المتجر ولوحة الإدارة
    services/     عميل API
```

## الصفحات والبيانات بتتحرك إزاي؟

- `/shop` هي صفحة المنتجات. بتطلب المنتجات والتصنيفات المتاحة من الـ API، وتدعم البحث والفلترة والترتيب وتقسيم النتائج إلى صفحات.
- `/product/:id` تعرض تفاصيل المنتج. قسم التقييمات موجود أسفل تفاصيل كل منتج؛ قراءة التقييمات متاحة للزائر، أما إضافة تقييم أو تعديله فتحتاج تسجيل الدخول.
- `/cart` تعرض السلة وتسمح بتعديل الكميات. زر المتابعة يفتح `/checkout` ولا ينشئ الطلب مباشرة.
- `/checkout` فيها خطوتان: عنوان وبيانات التوصيل، ثم مراجعة الطلب واختيار الدفع عند الاستلام. بعد نجاح الحفظ تفتح `/order-confirmation/:id`.
- الخادم يعيد حساب الأسعار والضريبة ويتحقق من المخزون قبل حفظ الطلب، ثم يخفض المخزون. الدفع بالبطاقة غير موصل حاليًا.

## قاعدة البيانات

قاعدة البيانات هي MongoDB، وليست ملفًا داخل مجلد الواجهة. عنوانها موجود في المتغير `MONGO_URI` داخل `back/.env`، لذلك يمكن تغيير مكانها دون تعديل كود الصفحات. في إعداد التطوير المحلي الحالي اسم القاعدة `clothes-store` على MongoDB المحلي. لا تضع قيمة `.env` أو كلمات المرور في مستودع Git.

الخادم يتصل بقاعدة البيانات عند تشغيله. ملفات `back/src/models` تصف البيانات التي يحفظها:

- `Product`: المنتجات، السعر، الفئة، الصور، المقاسات والمخزون.
- `User`: حسابات العملاء، ومع كل حساب السلة وقائمة الأمنيات.
- `Order`: الطلبات ونسخة من بيانات المنتجات والأسعار وقت الشراء.
- `Review`: تقييم مربوط بالمستخدم وبالمنتج؛ كل مستخدم يستطيع تقييم كل منتج مرة واحدة.

صور المنتجات المرفوعة تُحفظ كملفات في `back/uploads/`، بينما قاعدة البيانات تحفظ مسار الصورة فقط. الواجهة تتصل بالخادم من خلال `front/src/services/api.js`، والخادم يوفّر المسارات من `back/src/routes/` تحت `/api`.

## ملاحظات تشغيل وأمان

- جميع عمليات الطلب تتطلب تسجيل الدخول. الخادم يقرأ السعر والإجمالي من قاعدة البيانات، ويتحقق من المقاس واللون والمخزون قبل حفظ الطلب.
- الدفع الإلكتروني غير موصل حاليًا؛ المتاح هو الدفع عند الاستلام.
- قراءة الطلب وإلغاؤه محصوران بصاحب الحساب، والإلغاء متاح للطلبات المعلّقة فقط.
- لا توجد قيمة افتراضية آمنة لسر JWT أو اتصال قاعدة البيانات؛ يتوقف الخادم برسالة واضحة إذا غاب أحدهما.
- ملفات `.env` محلية وتحتوي أسرارًا؛ استخدم ملفات `.env.example` للمشاركة.
